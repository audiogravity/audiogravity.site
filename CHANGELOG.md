# Changelog — Audiogravi<sup>ty</sup>

All notable changes to Audiogravi<sup>ty</sup> (core, ui, license server, installers
and this landing) are documented here. Format based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [Unreleased]

### Added
- **[ops] [core] A box now answers to its own name, and its certificate carries that name.** Every certificate a box issues already promised `<hostname>.local` — the one address that keeps working when the router hands the box a different IP, which is the day every bookmark **and** every home-screen icon breaks at once, an installed app reopening for ever the address it was added from with no address bar and no error page to say why. Until now that name only answered by accident, on boxes whose owner happened to install AirPlay: its Debian package pulls in the service that announces names, and nothing else did. A box used as a local output or an HQPlayer endpoint had no reason to have it, so its certificate named an address nothing on the network answered to. That service is now installed, enabled and started with the rest — and if it cannot start, the install says so and carries on, because a box that cannot announce its name is still a box that works on its address. Two measured corrections came with it: the name is built from the **first label** of the hostname, which is what the announcing service actually publishes (a box called `musics.1` answers to `musics.local` and never to `musics.1.local`), and a certificate that does not carry that name is now reissued. Only the address was ever checked before, so a certificate naming the wrong one was served for its full term — up to 825 days — and nothing on a running box would have replaced it. The authority every device was told to trust is **not** reissued in the process, which is what keeps the phones and computers of the house from all having to be set up again.
- **[core] [ui] The support report answers what a certificate incident actually asks.** Five facts were missing, and a real case turned on every one of them: when the served certificate was **issued** — the day it changes is the day devices trusting it stop, and it was computable only by subtracting the issuing policy from the expiry, by hand; when the local **authority** was created and its fingerprint — an upgrade never reissues it, so those two tell "this authority changed, and every device stopped at once" from "this one device was never set up"; whether an interface's address is **leased or fixed**, which is whether it can still move; the name the box **announces**, asked of the announcing service itself rather than guessed from the hostname; and the **date** of the last self-update, since "done — 0.9.49 → 0.9.50" says nothing about whether that was an hour ago or last month. The report also flags an announced name its certificate does not carry — both facts were already in it, two sections apart, and nobody diffs them by eye.

- **[core] [ui] Qobuz browses like HIGHRESAUDIO does: five shelves, each opening a strip of its own.** Qobuz had four buttons — Favorites, New Releases, Selection, Playlists — two of which were a single hard-coded shelf apiece out of the many its catalogue holds, which is the same defect HIGHRESAUDIO's bar had before it was restructured. The bar is now **Favorites, Purchases, Shelves, Playlists, Genres**, using the strip mechanism the HIGHRESAUDIO menu already introduced; nothing new was built for it. **Shelves** lists **nine**: New Releases, All New Releases, Selection, Qobuzissims, Press Awards, Best Sellers, Most Streamed, Ideal Discography and Harmonia Mundi. Qobuz accepts fifteen names there and states them itself in the body of its own error; six are left out, each for a measured reason — `recent-releases` answers nothing at all, `most-featured` returns the same fifteen albums as `most-streamed` (two names, one shelf), and `universal-classic`, `universal-jazz`, `universal-jeunesse` and `universal-chanson` are one undifferentiated shelf whose content matches none of the four names, so it could not be labelled truthfully. **Purchases** is new and is Qobuz's answer to the HIGHRESAUDIO vault, but a simpler one: a bought album is read and played through the ordinary path, ids and all, so nothing about the queue had to change. **Playlists** gains the account's own beside the ones Qobuz publishes — they were simply never listed, though the route that reads their tracks already worked on them. Qobuz has no third tree: its two published names, `editor-picks` and `last-created`, answer the same playlists id for id. Asking for a shelf outside the nine now answers **400** rather than 503 — a request that can never succeed is not a service that is down — which also makes the six excluded ones genuinely unreachable rather than merely undocumented. **Genres** brings thirteen genres and seventy-eight sub-genres, none of which were reachable before. A genre is not a shelf on Qobuz — it only ever narrows one, which is why the genre grid browses the Selection: measured across eight sub-genres and four genres, a sub-genre returns nothing at all on the new releases and between one and thirty albums on the Selection. Two genres publish one sub-genre or none, which is the catalogue and not a failure.
- **[core] Qobuz search asks once instead of three times.** The same words were sent to the same endpoint three times over, once per kind of result, when leaving the kind out fills every one of them in a single answer — measured, 1.08 / 0.49 / 0.29 s for the one call against 2.87 / 0.64 / 0.70 s for the three. Album results also carry their year now, since every listing reads albums through one shared piece of code. There is no advanced search for Qobuz and there will not be one on their current API: the genre filter it accepts on a search is disregarded — four queries crossed with four genres each returned the same ten albums, filtered or not — and so are `hires`, `release_type`, `order` and `sort`. Filtering on our side would narrow the page of fifty rather than the catalogue, which is the very defect the local library's old *Recent* button had.

### Changed
- **[ui] The sign-in card and the footer carry the application's own icon, drawn the same way.** Beside the wordmark, the way the licence server's own sign-in sets it — the two now open on the same lockup. It is `apple-touch-180.png`, not the 512px icon: the same artwork, 61 kB instead of 465, and already in the service worker's precache, so on a box where the app is installed it costs no download at all. Sized at 36px against the mark's 42, which puts it a little taller than the capitals — the proportion that makes an icon and a name read as one block rather than a stamp set beside a word. On a dark card the icon needed help: its artwork is a near-black square, so it lost its edges against a card measured at #0a0a0a under Minimal and #12141c under Gravity, leaving the glyph floating with no bounds. A hairline in the theme's own border colour gives the square back its shape, rather than inventing a second, lighter icon — what the owner sees here stays what they see on their home screen. The footer already drew the same artwork, and drew it differently: 50px filling the bar's whole height, corners at 4 % of the side against the card's 22 %, so one square read as two marks depending on the screen. Both now name one shared rule, and the preview that opens when the footer icon is clicked joins them — its corners were flatter still. The radius is written as a proportion rather than a length, which is what lets the same rule serve a 36px icon and a 192px preview. And that footer icon is finally reachable: it opens a preview, but it was a bare image with a click handler, so no amount of tabbing ever landed on it and nothing announced it as something to press.

### Fixed
- **[site] Links to a section of the manual land on the section.** The manual's top bar stays on screen as you scroll, and nothing offset the headings for it: following a link to a section scrolled the page so the heading arrived exactly underneath that bar, out of sight. The reader landed mid-paragraph with no title to say where, which reads as a broken link. It affected every anchor in the manual, including the ones chapters use to point at each other and the FAQ on the landing page.
- **[core] Two lines of the support report said something they did not mean.** `no_license` reads as a verdict from the licence server; it is what a box reports when it holds no licence file at all and therefore sent nothing — the ordinary state of a trial, and a hunt for a problem that does not exist. And MPD's last error was printed bare, as if it had just happened: MPD keeps it until something clears it and never dates it, so a stale line was there to be blamed for tonight's symptom. Both now say what they are.

## [0.9.50] - 2026-08-31

### Added
- **[core] [ui] HIGHRESAUDIO's menu, laid out the way its publisher asked for it.** Their own audit put it plainly: eighteen pills ran end to end in a single bar, in the order their API happens to publish them, with the fourteen shop categories spilling off the edge — and the remark that started this was that the list needed organising, not lengthening. The bar is now **seven shelves** — Favorites, Vault, Categories, Charts, Playlists, Labels, Genres — each opening a strip of its own below it, which is the mechanism the genres already used; nothing new was built for it. Three shelves are new. **Charts** comes from an endpoint absent from their documentation and found in their own JavaScript client, as does **Labels**, which lists the seven they named, *2L* and *audite* included — five of those seven serve the same albums as the `… Highlights` categories, which is their catalogue and not a fault, so nothing is de-duplicated. And **Playlists** gains *Genre* and *Theme* beside *Editorial* and *Mine*: not a third tree but two of HRA's own groupings of the selections they publish, so a grouped browse asks for the editorial tree and names the grouping beside it. Their specification presents those two as filters of the playlist endpoint; measured, they are not — that endpoint answers *no data found* for a genre, and only the dedicated routes reply, which is why the code takes the longer path their document says is unnecessary. Nothing is hidden and nothing is re-arranged beyond the order they asked for: the six categories they named come first, in their sequence, and the other eight follow in HRA's. Three of the fourteen appear nowhere in their plan — *Bestsellers*, *UNAMAS*, *Featured Album* — and all three serve real albums (50, 50 and 26, and the first two share only nine titles, so they are not one list served twice), so removing them would have put catalogue out of reach. The one shelf they asked for that does not exist is *Explore*: two of its four entries are already categories, and the other two match nothing their API serves — not a category, a genre, a theme, one of the thirty-seven moods, or a label — so it is not built, and the question is with them.
- **[core] The genres and themes of HIGHRESAUDIO's playlists are listed alphabetically.** They arrive in an order that follows no rule anyone can read: the identifiers form a complete series yet come back as 4, 7, 5, 8, 1, 6, 3, 2, 9 — neither the identifier, nor the alphabet, nor the number of playlists, and no field in the answer explains it. Stable across repeated calls, so it may well be deliberate on their side; unreadable on ours either way, and a strip whose order cannot be predicted is worse for a listener than one that can. The same treatment the catalogue's own genres already had, at HIGHRESAUDIO's explicit request, and with the same key, so *R&B* still sits beside *Rock*. They are being told, so they can say if that order was a ranking after all — restoring it is one line.
- **[core] [ui] HIGHRESAUDIO's advanced search, copied from their own application, defects included.** Searching *Queen* returned a list with little to do with Queen, and filling in a filter with the search box left empty did nothing at all — no result, no message. Both causes were ours. Their advanced endpoint requires no search term (`label=ECM`, `composer=Bach`, `artist=Queen`, `genre=Jazz` and `format=fl192` each fill a page on their own, measured through the box), yet the box refused to ask below three characters — a rule that belongs to their *quick* search and was carried onto this one by mistake; and the interface only ran a search when the box held something, so the explanation it could have shown was unreachable. The form is now theirs, criterion for criterion: free text — the search box already on screen — **artist**, **composer**, **label**, **year**, **format**, **mood** and the **order**. Two fields are deliberately absent, and for different reasons. `album` belongs to their *shop's* nine-field form — a different back-end — and not to their application's, so copying the application leaves it out; the measurement only confirms nothing was lost, since the streaming API accepts it and disregards it (`artist=Queen&release=2026` returned the same thirteen albums id for id with no album, with `Innuendo`, and with a nonsense value). Genre is absent because it has a shelf of its own on the browse. **Year** is HRA's own name for the year an album went *online*, not the year it was recorded — *Innuendo* is production year 1991 and reads 2026 — and it is named as they name it. The **order** offers their nine entries; `+` sorts ascending and `-` descending, measured on all four criteria, and their own web client labels them the other way round, so the measurement is what the list follows. An order they do not know does not get ignored by them, it returns nothing at all, so the list is closed and anything outside it is refused rather than forwarded. One defect of theirs is passed through untouched, on purpose: setting a **format** discards the words typed — `queen` and `london` in FLAC 192 both return the same fifty albums, the whole 192 catalogue — which is how their application behaves, and a form that quietly behaved differently from the one people already use would be the worse surprise. A second one is passed through the same way: **mood** is accepted and disregarded — measured on a result small enough not to be capped, the same thirteen albums came back id for id with no mood, with *Amused* and with *Melancholic*, two moods of opposite families, and a mood on its own answers nothing at all. It stays because the field is theirs and because that class of defect is not a property of this one control: `album` and the direction of `importDate` are the other two. All three are reported to them. What the form does **not** do is ask a question that cannot be answered: an order with nothing to arrange returns an empty list, so the interface says *an order arranges results — add something to search for* rather than spending their slowest call to come back empty. The form is applied by its **Search** button rather than on every keystroke: this is the one slow endpoint they expose (measured on the box, three different cold searches each ran past thirty seconds and came back in about a second on the retry, their side having cached them), and the box runs two of them at a time, so seven controls each firing their own would queue behind one another.

### Fixed
- **[ui] HIGHRESAUDIO's playlist covers are shown whole.** Their audit said the artwork was a rectangle displayed as a square; measured on thirty-two of them, taken from the oldest to the newest of their catalogue, every single one is 410 × 205 — a banner, not a sleeve. Shown in a square cell, only the middle half survived, and these are compositions laid out across their width: the title and the label's mark are exactly what the crop threw away. The cell now takes the shape of the artwork. Each place keeps whichever dimension its layout owns — a card fixes its width, so the banner is half as tall; a list row fixes its height, so the thumbnail is twice as wide and the rhythm of a list mixing both shapes never changes from one row to the next. One defect came out of that change and was caught on a real screen rather than in a test: the row's cover column named a fixed width, so the wider thumbnail overflowed it and printed itself over the first third of every title. Nothing could have caught it in the test suite — the test environment lays nothing out — so the column now takes its width from the cell, and a guard reads the stylesheet rather than the DOM to refuse a hard-coded one.
- **[ui] The favourite star and the *add* button no longer sit on two lines in a search result.** A result row is a three-column layout — sleeve, text, one place at the end — and an album row on a streaming source carries **two** controls there, the star and the `+`. That is a fourth item for three places: the `+` wrapped onto a second line and came back at the far left, under the sleeve, with the star stranded alone on the right. It has been that way since the star was put on search rows on 2026-07-13, on Qobuz, Tidal and HIGHRESAUDIO alike, and it is the one screen in the application where a row carries both. The two now share a single place. The test environment lays nothing out, which is exactly why nothing caught it, so the guard counts the row's children instead — and refuses the other possible repair, a fourth column, which would leave a gap at the end of every row that carries only one control.
- **[core] A malformed row from HIGHRESAUDIO now costs one album, not a whole shelf.** Their answers are not typed, and two of the shelves come from endpoints missing from their documentation altogether. A row that was not an object raised where the album is built and turned the shelf into a server error, rather than into a grid one entry short — the three other places that read their lists already guarded against it.

### Changed
- **[ui] A streaming service is now shown by its own mark, and the library stopped pretending to report a state.** HIGHRESAUDIO already appeared as its logo above the album grid, because that logo *is* its name written out; Qobuz, Tidal and Roon were still spelled in capitals beside it. All four now carry their own artwork, in a light and a dark variant apiece, each set at its own size, because these four images do not hold the same thing: their proportions run from 1.4:1 to 7.5:1, the share of the picture the name itself occupies runs from 11 % to 99 %, and the ink each one paints on screen differed by a factor of two. So no single rule — one height, one width, one size of name — makes them comparable; the sizes are a judgement, and the stylesheet carries the measurements it was made from. HIGHRESAUDIO keeps the size its own composition needs, and Tidal stays the odd one: its logotype is spaced so widely that matching the others' weight would make it half again as long as any of them. Each stays an `<img>` with its name as alt text, never a CSS background: a background paints nothing at all when the file is missing or the browser is in forced-colours mode, and the line would then be empty with no way to tell which source is open. The green pulsing dot that opened that line is gone with them. It had exactly one value — there was no state it could report — so it announced "live" at the one moment that is true by construction: you have just chosen the source and its covers are already on screen. A status light that never changes is a word spent in advance, unavailable the day a source really is in difficulty; and it animated for as long as the page stayed open, on a machine whose CPU budget is a first-order constraint.

## [0.9.49] - 2026-08-29

### Added
- **[ui] Light or dark, decided before signing in.** The appearance switch lived in the configuration panel, which is behind the sign-in form: someone starting the box at night got the light palette full in the face until they were through it, and a reader who prefers dark had no way to say so on the one screen they always meet. A button now sits in the corner of the sign-in card — a moon on a light page, a sun on a dark one, always naming where pressing it takes you. It switches the *appearance*, not the theme: which of Minimal, Slate or Gravity applies is still chosen in the panel, and the button only flips that theme's palette. The choice is remembered where the pre-paint script reads it, so the next cold load opens dark with no white flash, and the browser's own chrome — the status bar of an app launched from a phone's home screen — follows in the same instant. The sequence behind both controls is now written once and shared, which is what the panel's switch had that the new button was missing: the event that repaints that chrome inside the application. Two faults found on the way, in code that had only ever run before the first paint and was now being called again on every flip: two thirds of the Safari remedy were absent, so a home-screen launch would have kept the old status-bar tint; and an unknown theme name — themes are extensible — threw *after* the palette and the stored preference had changed, leaving the switch half applied.

### Changed
- **[core] [ui] [ops] The interactive API reference is off unless a box asks for it.** `/docs`, `/redoc` and `/openapi.json` answered **without an API key** — they have to, since Swagger fetches the schema from the browser with no header of its own — so every box served the full map of its API to anything that could reach it: measured on a deployed core, 282 kB describing 188 routes, authentication, passkeys, licensing, system and self-update among them. None of it is an access, every route keeps its guard, but it is the floor plan, handed to an unauthenticated caller on a network that may hold a guest's phone or a compromised appliance. A new `API_DOCS_ENABLED` setting now governs the three routes together — together, because hiding the page while leaving the schema mounted would have removed the convenience and kept the exposure — and it ships **off**. They are unmounted rather than protected, so a request gets a plain 404: a route that does not exist should not answer 401. Boxes already installed are switched off at their next upgrade, and a box whose owner turned the reference on keeps it. The interface follows without being told: the core's entry point lists the endpoints it actually serves, `docs` is simply absent when they are not mounted, and the two buttons that opened Swagger disappear — a button leading to a 404 is worse than no button. Development keeps it on, which is also what the tooling that compares `API.md` to the live schema needs. One caveat for anyone switching it on: the Swagger page loads its own JavaScript from a CDN, so on a box with no route to the internet it opens blank.
- **[ui] The Audiogravi<sup>ty</sup> wordmark is set in type, the way the landing page sets it.** The interface drew its name from an SVG file, and that file was never a logo: it holds two text nodes asking for Helvetica, never converted to outlines. Every Linux and every Android the interface runs on lacks that face, so the mark was rendered in whatever the system substituted — different from device to device, while looking deliberate on the machine it was authored on — and dark mode had to repaint the image with a filter, because a picture cannot take a colour. The name is now text, in the typeface the interface already ships: same treatment as the landing page, down to the superscript *ty*, on the splash screen, the title bar, the sidebar, the sign-in card and the credit line of both footers. The splash screen was the last to keep its own version — capitals, wide tracking — and it had a reason the others did not: it paints before any theme exists, so it can read no token. Only its colour needed that exemption, which is why the shared class declares none. Sizes were matched to the capital height the drawn mark occupied, so nothing moved. The footers were a case of their own — they already wrote the brand correctly but without its styling, so it came out at the weight of the link around it with the browser's default superscript, more than twice the size the mark uses. Reaching the weight the landing uses required declaring the Inter faces over the range they actually carry: the files hold every weight from 100 to 900, the stylesheet claimed 400 to 700, and a declared range silently clamps the rest — the heaviest weight the interface asked for was being rendered one step lighter. The declaration costs no bytes: it is the same file.
- **[ui] The pipeline tab is named for what it shows.** Its heading read *AUDIO DSP PIPELINE*, on the desktop layout and on the mobile bar. There is no DSP stage: the placeholder node it once had left the diagram when the three services the box never shipped were removed, and signal processing is not on the roadmap. A title announcing a stage the page cannot show is a promise the page has to break.
- **[ui] The sign-in badge names the core, not "API".** `API · CONNECTED` above the form named a protocol nobody signing in has to think about; what the check actually reaches is the box's own core — the word the installer, the service unit and the rest of the interface already use for it. The footer of the application says `CORE:` before the address for the same reason; the button beside it keeps "API", since what it opens really is the API reference.
- **[ui] The configuration panel drops the word before its version number.** The footer of the panel read `Version: v0.9.49-dev`; the number and the icon beside it say what they are.

### Fixed
- **[ui] Five files the interface claimed to cache, and one it offered as an app icon, did not exist.** None of it failed in a way anyone could see. The service worker's app-shell list named three icons under names the repository has never carried — `apple-touch-icon.png` for `apple-touch-180.png`, `favicon-32x32.png` for `favicon-32.png`, `favicon-16x16.png` for `favicon-16.png` — beside two `logo_audiogravity_*.png` that exist nowhere at all; `cache.add()` catches its own failure, so this was five 404s on every install and update of the worker, and icons that were never actually precached. The push handler asked for two more absent files, so every notification was drawn with the browser's default glyph instead of the product's icon. And the web manifest offered the retired wordmark SVG as an app icon at `sizes: "any"` — the entry a browser reaches for first on a scalable surface — which should never have been there in the first place: that file is a logotype five and a half times wider than tall, and an app icon is square. All of them are now asserted against the repository: the precache list, the images the worker names elsewhere, and every manifest icon, shortcuts and screenshots included.
- **[core] An album the cover catalogues have never heard of showed no cover at all — even holding the picture.** Reported on HIGHRESAUDIO's Vault, where *HRA Mixed Up Sampler 2015.1* played with a blank sleeve in the player while the very same artwork appeared, correctly, on the *Up next* row two centimetres below. The queue row asks for the cover with the bare image URL; the player asks with the same URL plus the artist and album as a fallback. That fallback was the whole difference. Covers are cached twice — once per track, once per album so one fetch serves a whole record — and the album entry was being consulted **before** the URL the source had handed over. Cached as a miss it answered "no cover" outright, so the picture was never fetched: measured on the box at under 2 ms per refusal, while the URL served 83 kB of JPEG the moment it was asked directly. A miss on that entry only ever meant *MusicBrainz and iTunes know nothing about this album* — true of a promotional sampler, and of any obscure release on any source, and no reason to ignore artwork the service itself provided. The album entry may now answer only when it holds a cover; a miss still spares the two slow catalogue searches, which is what it was cached for. And the first track that resolves its own artwork writes it back, repairing the album for every other track instead of leaving them to wait out the cache.

## [0.9.48] - 2026-08-29

### Added
- **[core] [ui] HIGHRESAUDIO's Vault — the albums you bought, next to the ones you stream.** A *Vault* pill on the HIGHRESAUDIO source lists the account's purchases and plays them like any album: on MPD, on a UPnP renderer, through HQPlayer. HRA keeps purchases in a second tree with its own routes and its own ids — a purchased album is `<album>_<transaction>`, which the catalogue route refuses, and the catalogue search does not find it — so every Vault id carries a `vault:` prefix that travels back to the queue, the way a playlist id carries `mine:` or `editorial:`, and the proxy reads the prefix to resolve each track on the purchases route. It never reads the id's shape: three segments where the catalogue has two is what one purchased album showed, not something HRA documents, so an unprefixed three-segment id is logged and left alone. The two routes are not interchangeable, measured on the same session and the same purchased track — the purchases route answers, the catalogue route answers `NO SUBSCRIPTION` without a URL once the account has no subscription — and HRA's own §1.2 names the purchases route for exactly this. One trap on that route is guarded: handed an id of the wrong shape it answers `OK` with the metadata and no URL, which read as a success would enqueue silence. The purchases' own playlist tree stays unexposed: empty on both accounts available, so untested.
- **[core] [ui] An HIGHRESAUDIO account without a subscription can now sign in, and play what it owns.** The backlog said HRA refused such an account at the door; measured on one, HRA answers the login `NOK` / `NO_SUBSCRIPTION` **and ships a valid session in the same body** — one the purchases routes accept, down to a CDN that serves the FLAC (HTTP 206, `fLaC` magic). It was Audiogravi<sup>ty</sup>'s own login that refused, on the label alone, and it would then have recorded the account as subscribed. A session is now accepted whenever HRA issues one, the state is recorded in HRA's own words (`SUBSCRIPTION` / `NO SUBSCRIPTION`, the second absent from their documentation), and `/highresaudio/connection` carries `has_subscription`. The sources card says next to the account that it can play its purchases only, and the browse offers it the Vault alone — the favourites, the playlists and every shelf answer `NO SUBSCRIPTION` to that session, so a bar that offered them would offer buttons that fail. Search declines the same way — it covers the catalogue, so instead of running a query that can only answer `NO SUBSCRIPTION` it says so and points at the Vault. And signing a different account in on the sources card resets all of it at once: what the library offers, the cached shelves and the ★ state all follow the account that is actually connected, not the one that was. A core that predates the field is read as subscribed: that is the only state its login could ever have saved.
- **[site] The landing carousel says what each screen is.** Fourteen captures went past with nothing but a row of dots to tell them apart: a visitor saw a phone, not a product. Each now carries a sentence beside the device and three or four labels along its left edge, each one at the height of what it names and joined to the screen by a hairline — the source badge, the chain from service to DAC, the format actually being played, the output that can be switched mid-track. The labels are anchored to the capture rather than to the column, so the phone keeps its size and position whatever is written beside it, and their widths follow the free space instead of being fixed, which is what used to cut a sentence mid-word below 1856 px. They do not cross-fade with one another: consecutive screens deliberately share heights, so the outgoing label is gone before the incoming one starts, and only the visible screen's text is reachable — a transparent label is still found by Ctrl+F. Below 1550 px the flanks are too narrow to read and the labels are simply not shown.
- **[site] A DSD-over-HQPlayer capture joins the carousel.** UPnP feeding HQPlayer Embedded, DSD128 at 5.6 MHz, and the DAC receiving it — the one path the fourteen other screens never showed. The capture supplied was a full-resolution PNG at 1.5 MB; it ships as a 63 KB WebP at the 760×1497 of every other screen, its phone outline matching theirs to the pixel.
- **[site] The landing says what a finished streamer is made of.** A new *Board and software* section, between *Where it sits* and *How it compares*: network streamers sell for anywhere between a few hundred and several tens of thousands of euros, and for the part that makes one a streamer — receiving, decoding, handing the result to a DAC — it is a board running Linux with a software layer on top, most often the very layer Audiogravi<sup>ty</sup> drives. The claim is checkable rather than asserted: those components are GPL-licensed, so the manufacturer is obliged to list them, and the reader can settle it on their own machine. It names no brand and concedes the analog side outright — the DAC, the supply, the clocks are the reader's ground, and nothing has to be built: a Raspberry Pi, a fanless mini-PC or an Intel Mac mini with Linux on it is enough. Reuses `.rt-list` rather than adding a class that would style the same thing.

- **[core] Sending music to HQPlayer no longer reports success when nothing plays.** Audiogravi<sup>ty</sup> used to report the outcome of its conversation with HQPlayer, not the outcome of the playback: it answered "done" when HQPlayer had accepted the track but could not actually start (typically because the local sound card was still held by another player), and conversely answered with an error on a play that was working fine. It now checks that HQPlayer really started and reports the reason when it did not — *"its audio output is unavailable (most often the local sound card is still held by another player)"*.
- **[ui] Turning off "Use as output" for HQPlayer now gives the DAC back — local playback works again.** The toggle only changed where Audiogravi<sup>ty</sup> *sent* new plays; HQPlayer stayed loaded and its network audio daemon (NAA) kept the sound card open, so playing locally afterwards failed silently (`Failed to open ALSA device "hw:0,0": Device or resource busy`). Switching the toggle off — or disconnecting HQPlayer — now stops HQPlayer so the card is released. Casting to a network renderer was unaffected (it never uses the local card).
- **[core] Pausing a cast no longer makes the mini-player vanish.** A network-renderer cast (and any virtual source such as HQPlayer) is now kept visible in the mini-player while **Paused** — it was treated as "not playing" and filtered out, so pausing it collapsed the mini-player (the fullscreen was unaffected).
- **[core + ui] Seeking on a network renderer is more robust, and the progress bar follows.** A seek now tries both `ABS_TIME` and `REL_TIME` (some renderers advertise both but honour only one, e.g. upmpdcli); the new position is refreshed immediately so the progress bar jumps to it instead of appearing stuck for up to the 5-second poll interval (with an optimistic bar update for instant feedback). If the device rejects every seek method (UPnP 501 for an HTTP stream it can't seek) Audiogravi<sup>ty</sup> disables the seek control for that track instead of erroring repeatedly — it re-enables automatically on the next track.

### Changed
- **[core + ui] HQPlayer now appears as what it is — a processor in the audio chain, not a source.** When Audiogravi<sup>ty</sup> sends music to HQPlayer, the player badges the item with its real origin (**Library**) and the signal path shows the full processing chain (e.g. Library → HQPlayer Embedded → Music Streamer → DAC) — HQPlayer is a DSP step, not where the music comes from. When HQPlayer is driven outside Audiogravi<sup>ty</sup> (its own remote), the item shows **External** with the live format — the HQPlayer API does not expose the track title for external playback, so that sub-case is deliberately title-less for now. Transport commands and the DSD amplifier protection keep routing to HQPlayer through its (unchanged) internal routing identity; the DSD volume-slider exception and DSD-lock badge in the player now key on the routing identity too, which also extends them correctly to network-renderer casts (both are self-managed devices).
- **[core + ui] A cast to a network renderer now shows the content for what it is — the renderer becomes an output.** When you send music to a network renderer (a Marantz/Linn player, another Audiogravi<sup>ty</sup> box), the player now badges the item with its real origin — **Qobuz**, **Library**, the UPnP server's name, or **External** when another app drives the renderer — and shows the renderer as the **output** ("→ renderer name", output bar), instead of presenting the renderer itself as the source. Under the hood every now-playing item now carries two separate identities: what it **is** (display: `origin`, `played_on`) and what **plays it** (routing: `control_id`) — commands always go to the device that plays the content (MPD locally, the renderer for a cast), so play/pause/next keep working no matter how the item is badged. The player state gains a runtime **`outputs[]`** list (local DAC + selected renderer, with live transport state, built from in-memory caches only — zero added polling) with `active_output_id` and `queue_next`; a selected-but-stopped renderer stays visible through it (same on-screen result as before, no more synthetic "Stopped" item). The renderer's transport state now lives in **one** place (`outputs[]`): the player UI no longer consumes the `renderer_status` channel (kept for the Settings card), reactivity preserved via an event bridge (renderer GENA events → player state push, ~1s). The DSD amplifier protection is re-keyed on the routing identity, so a cast badged "Qobuz" can never have the renderer's physical volume forced to 100. Both control endpoints accept the new `control_id` handle (`source_id` still works).

### Refactored
- **[core] The Now Playing service is split into focused modules (behaviour-preserving).** The ~1550-line `now_playing.py` — which mixed playback-state aggregation, transport control, cover-art resolution and album tracklists — is broken into `stream_meta.py`, `album_tracks.py`, `cover_art.py` and `transport_control.py`; `now_playing.py` (now ~630 lines) only orchestrates and delegates. No API, event or behaviour change. The split adds 29 unit tests for the previously untested cover-art, album-tracklist and transport-dispatch paths, and folds the two duplicated MPD-escape helpers onto the canonical `core.mpd_client.escape`.

### Fixed
- **[core] Play/pause now works reliably on a native UPnP renderer.** Pause/Play were sent through a helper that silently did nothing whenever its cached "allowed actions" list (fed by device events some renderers deliver unreliably) went stale — so play/pause looked dead while volume and next kept working. Audiogravi<sup>ty</sup> now sends the AVTransport Pause/Play command directly to the device.
- **[core] Renderer state (play/pause, track, position) now updates in real time instead of lagging up to a minute.** The device-event callback was registered so that it rejected the actual UPnP `NOTIFY` requests (HTTP 405), and its no-API-key exemption never matched the real callback URL (HTTP 403) — so Audiogravi<sup>ty</sup> never received live events from a renderer and refreshed only via slow polling. Both are fixed; renderer state now follows within about a second. As part of this, after a pause/play command Audiogravi<sup>ty</sup> no longer briefly re-broadcasts the pre-command state.

### Security
- **[core] The unauthenticated UPnP renderer event callback is hardened.** The callback (which LAN renderers must reach with no API key) now only accepts events whose sender IP matches the renderer's own address, so a random host on the network can't inject spoofed playback state (it fails open for renderers that advertise a hostname rather than an IP, where the device-subscription id still guards). The API-key exemption for this callback is now an anchored path pattern that can't silently widen to a future nested route.
- **[core] Shared auth/infra hardened after a core code review.** `users.json` (bcrypt password hashes + passkey credentials) is now written atomically at `0600` — a crash mid-write can no longer truncate it into an empty file that would wipe every account (admin lockout), and it is no longer world-readable. Three unused debug endpoints were removed: `POST /publish/{channel}` (which let any API-key holder inject arbitrary events into any dashboard SSE channel — spoofed alerts/state), `GET /events/history/{channel}` and `GET /debug/sse/connections`. Password verification (`/auth/login` and the admin re-authentication on privileged actions) now runs bcrypt off the event loop, so a login attempt no longer freezes other requests / SSE for ~250 ms. A non-ASCII API key now fails closed with 403 instead of raising a 500, and stdlib log records get the same secret-redaction backstop that structlog already had.
- **[core] The systemd services module is hardened after a seventh code review — including a root-RCE fix.** Editing a service's tuning properties wrote them straight into a root `systemd` override file: fields like `CPUAffinity`, `TasksMax`, `LimitNOFILE`/`LimitNPROC` had no format validation, so a value containing a newline could inject an arbitrary directive (e.g. `ExecStartPre=`) that ran **as root** when the service restarted. Every property is now strictly validated (no newline/control characters), and the override generator refuses any embedded newline as a second layer. Lifecycle actions (start/stop/restart/enable/disable) and property edits are now restricted to **Audiogravi<sup>ty</sup>-managed units** — a standard user can no longer stop `ssh`, disable the AG backend, or kill networking through this API. The server always re-validates the override (`skip_validation` from the request is ignored), and the override file is forced to `root:root` ownership so it can't be rewritten without sudo.
- **[ui] Passkey login adapts to the anti-enumeration change on `/auth/webauthn/login/begin`.** The server now returns 200 with empty `allowCredentials` for an unknown or passkey-less username (instead of a 404), so the login flow no longer relies on that 404: when a typed username has no passkey the UI shows a clear "No passkey registered for this account" message instead of prompting for — and possibly offering — another account's resident passkey.
- **[core] Cover-art proxy, auth and config writes are hardened after a sixth code review.** The cover-art proxy (`GET /audio_pipeline/cover?token=url:…`) took a client-supplied URL and fetched it with no restriction — a server-side request forgery (SSRF) path to internal/link-local addresses (e.g. cloud metadata, AG's own loopback API). Cover fetches now go through an SSRF guard: only `http`/`https`, and hosts resolving to loopback or link-local are refused, while private LAN stays reachable (UPnP/MinimServer album art lives there); redirects are disabled so a public URL can't bounce into a blocked address. `POST /auth/webauthn/login/begin` no longer returns a distinct 404 for an unknown vs. passkey-less user (it always returns options), closing a username-enumeration oracle. Config writes now force `root:root` ownership so a same-filesystem move can't leave an `/etc` file writable by the service user. Config backups are pruned to the last 10 per service (they previously accumulated one per change, including each output switch).
- **[core] Package/engine downloads are hardened after a fifth code review.** Downloads of artifacts that AG then runs or installs as root (engine install scripts, `.deb` files, GPG keys) are now **HTTPS-only** — a plaintext HTTP URL is rejected, closing a man-in-the-middle path to arbitrary root code (APT repositories are unaffected: they legitimately use HTTP because apt verifies a pinned GPG signature). Downloads are also capped at 500 MB (the existing limit was never enforced) and given read timeouts so a stalled or oversized response can't fill the disk or hang an install. A trial with a start timestamp in the future (clock skew) no longer reports more than the full trial length.

### Fixed
- **[core] sysinfo / profiles / performance hardened after a fourth code review.** Applying a CPU governor no longer blocks the event loop: the sudo/sysfs writes run off the loop (a synchronous write per core could stall audio on a multi-core box), and an unknown CPU id now returns a clean error instead of a 500. A failed self-update *launch* (missing/misconfigured root wrapper) is reported as `failed` immediately instead of leaving the box showing "updating" for ~15 minutes. The critical-temperature and profile-activated push notifications keep a strong task reference so they can't be garbage-collected before they send (and the profile notification's completion callback no longer risks an error on cancellation). Bare `except:` clauses in the sysinfo service were narrowed so they no longer swallow task cancellation.
- **[core] Player / push / steering hardened after a third code review.** DSD playback no longer risks getting stuck at volume 100: a transient failure while forcing volumes to 100 at DSD start now keeps the saved original so it is restored when DSD ends. The subscriptions file is written 0600 from creation (shared atomic private-writer) with no world-readable window. The steering restart-fallback that rewrites `mpd.conf` now targets only the alsa output block and refuses to act on an ambiguous multi-output config instead of collapsing every output to one device. Steering's output-switched SSE events keep a strong task reference so they can't be dropped before firing.
- **[core] Playback modules hardened after a second code review (UPnP renderer / HQPlayer / library).** Qobuz browsing now recovers from an expired user session by actually re-logging in before retrying, instead of replaying the same token and misreporting the failure as rotated app credentials (which sent the user to re-extract the bundle for nothing); the HQPlayer status read tolerates a malformed numeric field instead of 500-ing the whole endpoint; a single-track HQPlayer play keeps its album in the now-playing card; and the UPnP renderer's short-lived background tasks (the play-state confirmation poll and the SID-mismatch resubscribe) now keep a strong reference so the GC can't collect them mid-flight.
- **[core] Streaming modules hardened after a code review (Tidal / Qobuz / HIGHRESAUDIO / Radio).** A batch of reliability fixes with no user-visible feature change: Tidal now drops an expired access token whenever a refresh fails (revoked session, network error) instead of replaying a dead token — this stops a per-request re-login storm and the misleading "client credentials rotated" error it caused; Qobuz sign-in no longer leaves a half-open connection (reported "connected" while streaming has no working secret) when the app-secret probe fails, and a bundle/network failure during sign-in now shows the styled error page (HTTP 502) instead of a raw *Internal Server Error* in the browser popup; the Qobuz app-bundle cache is now genuinely single-flight (concurrent cold-cache callers no longer each download the ~200 KB bundle); the Tidal remux proxy always cleans up its temporary files when a client disconnects mid-track (previously an orphan `.mpd`/`.part` could leak on cancellation); Radio favourites/library mutations no longer serialise behind a slow catalogue lookup, and the *Hi-Res only* search over-fetches so a page isn't starved down to a handful of stations. Hardened along the way: MPD argument escaping now strips newlines at the single choke point every MPD write passes through (defence-in-depth against control-character injection via a stream URL). Tidal also reuses the shared pooled HTTP session (keep-alive) instead of opening a fresh connection per track.

Discovery still surfaces it — shown as a non-selectable *"This device · receives external casts"* info row for transparency — but AG now refuses a connect to it (`400`) and, on upgrade, drops it from any persisted active output (falls back to the Local DAC). ### Fixed
- **[install] a fresh core install no longer aborts before the service is created** — the installer's optional VAPID key generation exited non-zero (and imported a non-existent `cryptography.hazmat.cores` module) on a box without the `cryptography` lib or a pre-existing `vapid_keys.json`; under `set -e` that killed the install before `ag-core-server` was created (binary placed, service missing). VAPID generation is now guarded and non-fatal (push notifications simply stay disabled).
- **[core] password-gated admin actions (audio-stack provision, license deletion, system reboot) now work when JWT auth is disabled** — they re-authenticated by looking up the token's user, which does not exist under the JWT-disabled bypass admin, so they always returned 401. - **[core] a Qobuz / HIGHRESAUDIO track cast to a local MPD output no longer fails (403) once its CDN URL expires** — the MPD queue now holds a stable proxy URL that 302-redirects to a freshly-resolved CDN URL on each fetch (MPD follows the redirect), instead of a raw, time-limited CDN URL that would 403 for a track still sitting in the queue past its ~hour TTL (paused, deep in a long queue, or resumed later). AG relays no audio bytes (the 302 sends MPD straight to the CDN) and no per-track CDN resolution happens at enqueue. Tidal already used stable proxy URLs (unchanged).
- Streaming proxy (Qobuz + HIGHRESAUDIO): pre-signed CDN URLs are now fetched byte-for-byte, so a reserved character in the signed token is never re-encoded (which could cause a 403 and a track failing to play). The Qobuz and HRA proxies now share a single `core.http.proxy_cdn_stream` helper.
- **[core] player transport controls now route through the UPnP renderer that owns the queue** — when a streaming source (Qobuz / Tidal / HIGHRESAUDIO) is cast to a *network* renderer, `next` / `prev` / `pause` / `stop` / `seek` / `volume` go through the renderer's AVTransport (`advance_queue` / `pause` / …) instead of driving the underlying MPD directly. ## [0.9.1] - 2026-06-07

Changes since **0.9.0**. Range: `74a7897` (0.9.0 baseline — *Merge
feat/hqplayer-integration into master*, 2026-05-30) → release HEAD. The earlier
`v0.9.1` git tag (`b3ab0c2`) was never a release and is superseded by this one.


**Focus: ARM/Debian (aarch64) portability.** Audiogravi<sup>ty</sup> now installs and runs on
aarch64 (Raspberry Pi 4 / Debian) **alongside** x86/DietPi — with the absolute
constraint of never regressing the existing x86/DietPi target. This cycle also
hardens the install/packaging path, configures the production environment at
install time, fixes the standalone prod server (SSE + WebSocket), and adds test
coverage. Period: 2026-05-30 → 2026-06-07.

### Added
- **ARM64 (aarch64) as a first-class target** — backend, frontend, license server
  and audio-software installs validated end-to-end on a Raspberry Pi 4 (Debian),
  with x86/DietPi kept non-regressed.
- **[ops] upmpdcli on ARM64** — `scripts/build-upmpdcli-arm64.sh` builds the
  libnpupnp → libupnpp → upmpdcli chain natively for aarch64 and publishes a
  checksum-verified `.deb` bundle on `audiogravity.app`. The package registry
  installs it via a per-arch `arch_fallback` (no upstream arm64 package exists
  anywhere); the official source still wins where it covers the arch.
- **[ops] WebAuthn passkeys at install** — `--public-url` sets
  `WEBAUTHN_ORIGIN` and derives `WEBAUTHN_RP_ID`; forwarded by the bootstrap and
  all-in-one installers and documented in the README (passkeys require a real
  HTTPS domain, not a bare IP).
- **[ops] Push contact** — `--vapid-email` sets the VAPID `sub`; forwarded by
  the installers.
- **[ui] HQPlayer manual IP entry** — connect to a HQPlayer on a different
  (but routable) subnet that the local /24 discovery scan can't reach.
- **[ui] Standalone server WebSocket proxy** — the prod Python server now
  proxies the admin terminal WebSocket (`/sysinfo/terminal/ws`) via raw tunneling.
- **[site] Page** — the "Releases" link now points to the public GitHub repo;
  install section clarified (works on the LAN by default, passkeys/push moved to an
  optional block that requires a public domain); portable local preview `dev.sh`
  (auto-detected LAN IP).
- **[ops] Deterministic dependencies** — `requirements.lock` (68 packages pinned,
  wheels verified for x86_64 **and** aarch64, Python 3.13.5) + runtime/build split
  (`requirements-dev.lock`); license server dev requirements (`requirements-dev.txt`).
- **[core]** — VAPID key loading, PayPal IPN webhook flow (8 tests), and scoped
  pytest warning filters for third-party deprecations.

### Changed
- **[core] Auth** — replaced `passlib` with direct `bcrypt` calls.
- **[ui] Prod server consolidation** — the frontend package now bundles the
  canonical `serve_https.py` (line-by-line SSE streaming + gzip) instead of a
  divergent, broken inline copy; the systemd unit invokes it with args +
  `WorkingDirectory`.
- **[ops] Production `.env` configured at install** — license server URL/key,
  VAPID, and `ENABLED_MODULES` (incl. `hqplayer`).
- **[ops] `build-backend.sh` self-bootstraps** — installs system prerequisites
  and `python3`; the generated installer uses non-interactive `apt`; deps synced
  via `pip install -r` with wheels only.

### Fixed
- **[ui] Prod SSE stuck on "Connecting…"** — the packaged proxy buffered the
  event stream (`shutil.copyfileobj`); now streamed so the UI connects.
- **[ui] Broken-pipe traceback noise** in the standalone server when a client
  drops a keep-alive connection (e.g. after closing an SSE tab).
- **[core] Runtime bugs surfaced on ARM** — CPU model (lscpu fallback), governor
  field (`current_governor`), `cpu-governor.service` boot script (stdlib `json`),
  and `ORJSONResponse` deprecation warnings.
- **[core] Service config paths** resolved across OS layouts (`/etc` vs
  `/usr/local/etc`) and reloaded when software is installed/removed at runtime.
- **[core] `hqplayer` module** missing from the packaged `.env` `ENABLED_MODULES`
  (its endpoints returned 404).
- **[core] aarch64 startup crash** — caused by `passlib` vs `bcrypt>=4.1`.
- **[ops] Audio-software install made arch-aware** — Roon per-arch URLs
  (`{roon_arch}`), download allowlist, stdin for interactive vendor installers, and
  complete uninstall; upmpdcli `.deb` ships its systemd unit, creates its system
  user, and stops/disables cleanly on removal.
- **[ops] sudoers** completed (including Roon uninstall) and hardened
  (`sudo tee` instead of `sudo sh -c`).
- **[ops] Nuitka / packaging** — explicit includes (psutil, distro, orjson,
  pydantic, ntplib), `SHA256SUMS` merge + checksum verification in installers,
  missing transitive deps (pyparsing, ifaddr), `gh` auto-install, `license.pub`
  lookup, and miscellaneous installer robustness fixes.
- **[ops] Environment scripts** — no longer hardcode `/home/dietpi` paths or LAN
  IPs (runtime detection); seed a default `admin` user; provision dev sudoers/polkit;
  resolve `visudo` by absolute path on DietPi.

### Removed
- **[ops]** obsolete `backend/update.sh` (incompatible with the Nuitka-binary
  production model).
